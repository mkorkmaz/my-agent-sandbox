Why sandbox a coding agent?

Ask an agent to run tests, and it may first install a dependency. In your Mac terminal, a faulty setup script could overwrite files in another project.

Brig runs each agent in its own microVM, a small virtual machine on your Mac. Each guest has its own Linux kernel and home directory. Both guests can edit the project folder you share.

Files and tools
A setup script can replace a tool inside the guest without replacing the one on your Mac. Mac folders outside the sharing plan stay out of reach.
Network access
You choose which hosts guest commands can contact. The policy denies other destinations by default. A permitted host can still receive project data.
Account access
The guest gets an access token so the agent can make requests. The credential that renews your provider sign-in stays on your Mac.

The shared folder is still writable.

If an agent deletes a file there, it also disappears from your Mac. Commit or back up work you need to keep. The Open local terminal action runs directly on your Mac, outside the sandbox.

Frequently asked questions

Why does Tugboat use Brig instead of Docker Sandboxes?

Brig puts the network rules outside the agent’s control. A gateway on your Mac filters outgoing packets from the agent and any install script it runs. Tugboat requires a policy that denies connections by default. Brig can allow specific hosts or IP address ranges. If the runtime cannot enforce the policy, Brig refuses to start the sandbox.

Brig’s optional credential broker can keep a key on the host and use it only for an allowed request, down to the HTTP method, path or Git repository. For ChatGPT and Claude sign-in, Tugboat gives the guest an access token and keeps the refresh token on your Mac.

Docker Sandboxes (sbx) also uses microVMs. It enforces network rules through host-side proxies and can add credentials to outgoing requests. Brig lets us inspect the gateway code and the tests that show which connections it allows or blocks.

Which parts of a chat run on my Mac?

The agent edits files and runs commands inside its sandbox on your Mac. It sends requests to its model provider for responses. Those requests can include code and command output from your project.

What happens to my work when I stop a sandbox?

Your edits are already in the project folder on your Mac. Stopping the sandbox ends that agent’s running processes. Tugboat keeps its guest home and saved chats, so you can resume a conversation later.

Why the name Tugboat?

A ship can cross an ocean under its own power and still need a harbor tug to ease it sideways to the dock.

Your Mac is the harbor. Your project folder is the dock. Codex and Claude Code are the ships. Tugboat brings them alongside the same project and gives each its own berth. In the app, that berth is a sandbox. Both agents can edit the folder you share, and you choose which network destinations each can reach.
