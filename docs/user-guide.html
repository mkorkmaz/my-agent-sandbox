Tugboat user guide

Run a coding agent on a local project, review what it changed, and return to the same chat later. This guide describes Tugboat 0.3.0 for macOS.

Start your first chat

You need an Apple silicon Mac with macOS 15 or later, a local folder you can edit, and an account for your chosen agent. The first environment download needs an internet connection. The packaged app includes Brig, the software that prepares the isolated environment. Homebrew and a separate Mac installation of either agent are optional.

For a Developer ID signed and Apple-notarized disk image, open the image and drag Tugboat to Applications. Start Tugboat from Applications. For a local development build, see the instructions in the project README.

  1. Open Settings. Select System Checks and then Check this Mac. Look for Brig installed and the selected Brig version. Expand Brig doctor results to read each finding.
  2. Open Providers. Select Sign in with ChatGPT for Codex or Sign in with Claude for Claude Code. Complete authorization in the browser. Return when the provider card shows the connected account.
  3. Open Projects. Select Add new project. Choose the folder that contains the project. Both agents can change files in that folder on your Mac.
  4. Choose Codex or Claude Code in the selector beside New Chat. Tugboat prepares the selected environment in the background. The first start can download the guest image and boot files.
  5. If Tugboat asks for a choice, open Review project settings. Check the Sharing and execution plan. Resolve any session or policy request. Wait for preparation to finish.
  6. Select New Chat. Type a request in the terminal. For a first request, try Name the test command for this project and show me where it is defined.
  7. Select Return to project. Select the chat in the sidebar to return to its terminal. Its previous output stays visible while the terminal is open.

The Writable folder in the plan is the folder on your Mac. Edits under the corresponding Guest project path change those files directly. Choose only the folder you intend to share.

Connect and manage accounts

A provider account serves its agent across projects on this Mac. Each agent still has a separate environment, guest home, network policy, and chat history for each project. You can connect either provider before adding a folder.

Which account and profile to use
AgentBrowser sign-inInside the environment
CodexChoose Sign in with ChatGPT. Enter the ChatGPT device code from Tugboat on the official page opened by Tugboat.The default profile is codex. Tugboat installs a managed sign-in copy in the standard guest Codex location. A custom credential location or profile file or volume mapping can prevent this step.
Claude CodeChoose Sign in with Claude. Complete authorization in the browser on this Mac. The browser returns the result to Tugboat through a temporary local connection.Shared sign-in requires an environment that Tugboat created with tugboat-claude. Its access copy lives in guest memory. Stopping the environment clears that copy. Starting a chat restores it from your shared account.

Leave Tugboat open during authorization. Use Return to browser if you close or lose the browser tab. Use Cancel sign-in while available to abandon the attempt. Keep device codes private. Tugboat stores renewable credentials in its private records folder on the Mac. Guests receive access copies without the renewal credential.

Use an existing ChatGPT sign-in

If Saved project sign-in appears, check the account, project name, and path. End Codex processes for the source project. Select Use saved sign-in. Choose the intended source when different projects belong to different users or workspaces. A fresh browser sign-in is also available.

Check, change, or disconnect an account

Open Settings and then Providers. Use Check connection to renew the account. If Tugboat reports a transfer or renewal failure, follow the message and use Retry connection when offered. Use Finish connection if a ChatGPT transfer is waiting to finish.

Before switching accounts or signing out, finish work in that provider’s chats and guest terminals across projects. Close those processes. Select Sign in with another account to switch, or Sign out of Tugboat to disconnect. Read the result. If remote revocation was unconfirmed, review that session in the provider’s account settings. Account changes preserve project files and chat history.

Choose a project and environment

The Projects library lists folders in order of last use. Hover over a name to see its path. A Git project also shows the current branch when Tugboat can read it. Selecting a row opens its dashboard. The project header shows the folder and the Brig reference, such as codex@….

A Brig environment is the guest system that runs the agent. A chat is one conversation inside that environment. You can open several chats in an environment. Both agent environments see the same project files. For example, a change that Codex makes to a source file is also visible to Claude Code in this project.

New folders start with the default Codex environment. Use the selector beside New Chat to select the Claude Code environment. Changing this selector also changes the target of project settings and guest operations. The session table continues to show both agents. Check the agent beside the chat title when two titles are similar.

Read the execution plan

  1. Open the Project settings button in the project header. If setup needs your attention, you can also use Review project settings.
  2. If Existing Brig session appears, select the session for this folder and agent. Select Use this session. Tugboat can reuse a single matching session automatically.
  3. Expand Sharing and execution plan. Check the host folder, guest path, and guest home. Check resources, runtime, image signature, attached policies, allowed destinations, and listed host credentials.
  4. Use Refresh plan after an external change. Use Prepare environment if a reviewed plan still needs to start or verify its guest.

On later visits, Tugboat can show saved history while it starts the selected environment. It reuses a running environment after checking its identity and plan. Codex waits for the project account to sync before enabling New Chat. Claude enables the button when its environment and app account are ready. It checks guest access when you start the chat.

Work with chats and terminals

Start a separate conversation with New Chat. Select a running chat in the sidebar to switch its terminal into view. Other chats continue running. Codex can show a working indicator beside its title. For Claude Code, read the terminal to see progress and permission requests.

Choose a terminal action
GoalAction and result
Leave a chat runningSelect Return to project. Select the chat again to see the same process and its scrollback.
Continue a saved chatSelect its title in Sessions. Tugboat uses the environment that owns the chat. If prompted, prepare that environment first. Claude resumes the same native conversation ID.
End one processSave any unfinished terminal input. Select Close terminal while that terminal is running. The selected process ends. An agent chat with a saved transcript can be resumed later.
Read command output againOpen the project’s Terminals list. Select the test, diagnostic, or other operation. Its caption shows whether it is running or how it ended. Close output discards that view.
Run a guest commandOpen Project settings. Choose Guest terminal after preparation. Commands run in the selected Brig environment under its policy. Opening a shell can require an existing process to end.
Run a Mac commandExpand Changes and environment management in project settings. Open local terminal starts a shell on the Mac in the project folder. Guest network and file restrictions apply only inside the guest.

Tugboat supports up to 16 live terminal processes at once. It retains up to 32 completed terminal views during the current app session. The oldest completed views close when this limit is reached. Copy any test output you need later before quitting.

Organize saved chats

Use the action icons at the end of a session row. Hover over an icon for its label. Archive moves a chat to Archived. Delete moves it to Trash. Restore in either view returns it to Sessions. Restore a chat from Trash before resuming it.

Finish the root chat and any running subagents before archiving or deleting it. A subagent is an agent started by another agent for part of a task. Its recorded work belongs with the root chat when Tugboat can verify their relationship. These list actions preserve the native transcripts and recorded project totals. Use the sidebar’s Refresh button to read the latest session list.

Set resources and network access

Settings → General supplies app defaults. Agent Profile selects the profile used to set up new environments for each agent. Use Save settings after editing either tab. For an existing project, open its settings and check the Brig reference at the top.

If both environments are running, stop the first, switch to the second, and stop it. Save from the second environment. Switching back can restart the first.

The default Codex host list contains auth.openai.com, chatgpt.com, and api.openai.com. Claude Code starts with api.anthropic.com, platform.claude.com, and claude.ai. A project that downloads dependencies can require additional destinations.

Allow a destination for one existing environment

  1. Select the intended agent beside New Chat. Finish active work in that environment.
  2. Open Project settings. Expand Changes and environment management. Select Stop Brig environment.
  3. Expand Project network policy. Select Read or refresh policy. Check the existing document and host list.
  4. Add the required host under Allowed guest hosts for this project. Keep the existing hosts you still need. Select Save allowed hosts.
  5. Review the updated plan. Start the environment again when prompted. Retry the command that needed the destination.

A policy shared with other sessions, an externally managed policy, or one with advanced rules is read-only in this editor. Have its owner review requested changes. If an external change was intentional, read its current document before choosing Accept this policy version. Use Attach to this session for a detached policy. A detached policy blocks environment preparation.

Understand agent permissions

Under File and network boundaries, Codex starts with Use the Brig boundary with the agent sandbox disabled selected. In that mode Codex has full access inside the guest. Brig still controls Mac folder sharing and guest network traffic. Codex does not ask for command approval.

To use the extra Codex workspace sandbox, clear that option before you start or resume a chat. Codex can write within the workspace and disables network access from its commands. The approval setting remains never. Check the option again after changing the project or plan. A running chat keeps the mode it started with.

Claude Code uses the Brig boundary and asks for permission in its terminal when required. Read the proposed action before answering. Tugboat offers the workspace sandbox control for Codex only.

Check Brig boundaries tests file sharing and network behavior in the current environment. Compare the expected and observed results. An inconclusive result can mean two hosts share an address or the active policy has no suitable comparison host. The check reports observations. It does not change the policy. Hosted tools such as Codex web search operate separately from guest commands. A hosted result cannot establish that the guest reached that site.

Review changes and run tests

Suppose an agent reports that it changed a function and added a test. Leave the chat running with Return to project. Select its agent and open Project settings → Changes and environment management.

  1. Choose Git status. Read the modified, staged, and untracked file names. After each command, choose Return to project and reopen project settings for the next command.
  2. Choose Working tree diff to inspect unstaged changes to tracked files. Choose Staged diff to inspect changes already staged in Git. New, untracked files appear in status and need separate inspection.
  3. Choose Run project tests. The test uses the selected guest and runs in its own terminal. Inspect the output and exit code when the test ends.
  4. Select the original chat when you are ready to continue. Open Terminals to compare the results from earlier operations.

Tugboat checks for a test command at the project root. It tries a configured npm test script, a Composer test script, a Cargo project, then a pytest configuration. The first match runs. A monorepo can have its test configuration in a subfolder. Use Guest terminal and run the project’s documented command there if detection finds no test. Guest tests operate on the shared files and need their own tools and dependencies.

For an environment problem, choose Brig doctor to check its profile. Choose Session info to verify the session target. Policy bindings shows the policies attached to it. Recent logs opens up to 100 recent lines for that session. These results also appear under Terminals.

Read usage and cost

The dashboard shows recorded usage for the project across both agents. A token is a unit that the provider uses to measure model input or output. Cached input shows tokens read from a cache and their share of input when known. In Claude Code, total input includes ordinary input, cache reads, and cache creation. A cached input count is already part of input.

  1. Hover over an abbreviated count in a session row to read the exact recorded counts. Open the information control beside Total API cost to inspect the scope and pricing notes.
  2. Choose the row’s Usage icon to open Session usage. Compare Main agent, Subagents, and Combined when available. The root chat’s row already includes its linked subagents.
  3. Expand a subagent to see its turns and requests. A turn can contain several requests. Use the source links, when available, to follow a prompt to the measured request.
  4. Check a request’s model, tier, pricing date, and assumptions before comparing its cost with another request. Use the provider’s billing statement for an actual charge.
How to interpret the labels
DisplayMeaning
Total API costAn estimate in US dollars using recorded token counts and saved application programming interface (API) rates. Subscription fees, discounts, server tool charges, and taxes fall outside this figure.
Unknown or + unknownA record lacks a count or some turns lack measurements. A known subtotal can still appear. A measured zero and a missing measurement have different meanings.
Unpriced or + unpricedTugboat lacks a supported rate or required billing details for one or more requests. Known token counts still contribute to totals. An unpriced request can still have a provider charge.
Estimate or assumedTugboat used a saved rate with a stated assumption. For Claude, examples include speed, geography, or the lifetime of a cache write. Read the request details for the applied values.
Recorded source coverageComplete, partial, or unknown describes what the available source records establish. Even complete recorded coverage can include an unpriced request. Claude coverage is partial because some subagent work can lack records.
Unassigned to a user promptThe work belongs to the selected scope, but Tugboat could not prove which user prompt caused it. Its recorded usage still counts. Claude Code does not provide verified prompt attribution here.
Unlinked subagentsTugboat found subagent records without a verified parent. Inspect Usage in this section. These entries have read-only history and cannot be resumed separately.

Project totals include recorded work from Archived and Trash. For example, deleting a session can reduce the number of visible chats without reducing the total. A temporarily unavailable transcript can also leave a saved total on screen. Resuming the chat still requires its source transcript.

Move or reconnect your records

Your project folder contains your working files. Brig maintains the guest homes that hold native agent history. Tugboat keeps a third location for its own settings, project list, account records, saved usage, and checks. Find it under Settings → General → Records folder. Its default path is ~/Library/Application Support/Tugboat.

Move records to another folder

  1. Choose an empty folder owned by your Mac user account. Keep it outside every project, guest home, and the current records folder. Its volume must support private file permissions.
  2. Select Change folder…. Choose the destination. Read the pending path shown in Settings. Use Cancel folder change if it is incorrect.
  3. Save any pending settings or terminal work. Select Restart Tugboat. If a process is running, Tugboat asks before ending it.
  4. After restart, open Records folder. Check the active location. Open a known project and check its saved usage.

Tugboat finishes recording usage and verifies the copy before switching locations. The move includes the closed usage database, retained older records, backups, and both shared accounts. Project files and guest homes stay in their own locations. Use default folder schedules the move back.

Reconnect a missing disk

If the records drive is absent, connect the original drive and restart Tugboat. If the same records now have a different path, choose Locate records folder…. Select the complete records folder that belongs to this installation. Restart when prompted. A partial copy or a folder from another installation will fail the identity check.

If Usage storage is unavailable appears, preserve the entire records folder, including usage.sqlite3 and usage.sqlite3-journal if present. Reconnect the original drive first. If the active database is missing or damaged, obtain help restoring a verified matching backup with Tugboat closed. Avoid copying an open database, deleting its journal, or downgrading to an older ledger writer. Retained older ledgers can lack the latest usage.

Stop, forget, or remove

What each action affects
ActionTarget and consequence
Stop Brig environmentStops the selected agent environment and its processes. The project files, guest home, saved conversations, and other agent environment remain available. Select Start environment to use it again. Reopening the project can start its selected environment automatically.
Quit TugboatFinishes the app session. If processes are running, Cancel keeps them open. End processes and close ends them and records final usage. Brig environments and saved chat history persist.
Forget…Appears on a Folder unavailable row in Projects. End any running project terminal first. Confirm Forget record to remove the library entry and stop monitoring it. Project files, Brig environments, guest homes, and recorded usage stay on disk.
Preview environment removal…Reviews removal of the selected agent environment. An existing guest home and its transcripts can be removed. The preview lists the exact session, guest home, bindings, and policy. Project files are preserved.
Preview all environments…Reviews every agent environment registered to this project. Removing its last environment also removes its project entry. This action can affect both agents’ guest histories.

To remove an environment, open Project settings → Changes and environment management. Select the preview with the intended scope. Review every path, including sessions created outside Tugboat. Keep a separate copy of guest work you need before continuing. Type the displayed confirmation name exactly and select Remove session. Use Cancel to leave the preview. Removing one environment preserves the shared provider accounts used by other projects.

If removal stops partway through, open Review incomplete removal…. Check the recorded steps and the remaining target in the new preview. Setup stays paused for the affected environment until the operation completes.

Find a problem by symptom

Start with the control closest to the failure. A Mac runtime check, a provider connection check, and a guest policy check answer different questions.

  • Installation and runtime

Installation and runtime

macOS cannot verify the downloaded app
Check that the disk image is for Apple silicon. Check how the distributor signed and notarized that specific build. A development image with an ad hoc signature can fail Gatekeeper. Obtain a verified distribution build or use the local development installation instructions. Installation notes.
“Brig not found”, “Unsupported Brig version”, or a bundled tool fails verification
Open Settings → General. Check Brig CLI path. Clear an obsolete custom path to select bundled Brig. Select Save settings. Run System Checks → Check this Mac again. If a bundled tool is missing or damaged, reinstall the app from a trusted copy. Changing guest settings cannot repair the Mac package.
The Mac check times out or shows an old result
Read the status above Brig doctor results. A cancelled or timed-out check can leave the previous completed check visible for the same Brig path. Run Check this Mac again and wait for completion. A boot-image download finding on a fresh Mac can coexist with a valid installed runtime.

Projects and preparation

A project shows “Folder unavailable”
Check its path in the library tooltip. Connect the original drive and keep Projects visible. Tugboat checks unavailable folders about every eight seconds and when the window regains focus. If you moved the original folder, use Add new project to select it again. A different folder with the same name can still have a different identity. Use Forget… only when you intend to discard the library record.
A folder fails registration or cannot be mounted
Choose a directory your Mac account can read and write. Check the folder name for tabs, line breaks, or quotation marks if mounting fails. Spaces are supported by the bundled runtime. Keep private Tugboat records outside both the project and the guest home.
Setup asks for a session or refuses a changed plan
Open Review project settings. Match Existing Brig session to the intended folder and agent. If the policy changed, read the current policy and review the allowed destinations. Reattach a detached policy. Use Refresh plan or Retry setup, as offered. If the reported home or project belongs to another session, correct the selection before starting it.
Environment startup fails after a plan appears
Open Environment startup under Terminals. Check the specific runtime, image, or guest agent error. Confirm that the Mac has internet access for its initial downloads and that the selected profile runs the intended agent. Run Brig doctor for that profile. After correcting the cause, select Retry environment. An explicit stop instead offers Start environment.
A saved project setting cannot be changed
Inspect the agent and session reference in project settings. Close live terminals that affect the change. Stop the selected environment before editing. If you changed processor count, memory, or image verification, stop the project’s other running agent environment too. Save with Save project settings. The project name is a library label and can contain 1 to 120 characters.

Sign-in and New Chat

Authorization did not finish in the browser
Go back to Settings → Providers. Read the message for the intended provider. While it waits, select Return to browser. Use the current ChatGPT device code, or complete the Claude browser flow on the same Mac. If the attempt expired, start a fresh sign-in. Copy only the error text when reporting a problem.
The account is connected but New Chat is unavailable or its launch fails
Confirm the selected agent matches the account. Read the project status for a pending environment check. Use Open application settings… if shown. Check the provider connection there. Inspect the selected environment’s network mode and allowed provider hosts. A Mac browser authorization can succeed while the guest is offline.
A provider copy cannot be updated, or a process blocks sign-out
Finish that provider’s active chats and guest shells. For an older Codex process that remains active, stop and reopen the affected environment. Use Check connection or Retry connection. Sign in again if Tugboat says the account needs sign-in. If Claude reports an unsupported profile, check that Tugboat created the environment with tugboat-claude.

Network, tests, and terminals

A guest cannot reach a host after you changed Settings
Inspect the Sharing and execution plan in the affected project. The app host list initializes new policies. Read and update the active Project network policy for an existing environment. Check the exact host name, network mode, and agent. In the optional Codex workspace sandbox, command network access stays disabled. Change a project policy.
A boundary check failed or was inconclusive
Read each probe’s target, expected result, and observed result. Offline and deny-all policies expect blocked connections. Shared network addresses and advanced rules can prevent a reliable comparison. Review the effective plan and run Check Brig boundaries after any correction. Use Copy Codex sandbox check in the same Codex conversation to inspect the extra sandbox if you enabled it.
“No test command is configured” or a test exits with an error
Check the project root and the supported test configuration. For a custom command or nested package, open a guest terminal in the correct environment. Run the project’s documented test there. If a detected test fails, read its terminal output for the missing dependency, blocked host, or failed assertion. The exit code alone does not identify the cause.
A terminal cannot open or an old result disappeared
If Tugboat names a conflicting process, return to that terminal. Finish its work and choose Close terminal. At the 16-process limit, close an unused live process. Closing an old completed output does not free a live process slot. Check the correct project’s Terminals list for saved output. A closed, expired, or previous app session’s terminal view cannot be reopened.

Chat history and usage

A chat disappeared from the sidebar or cannot be resumed
Open the correct project. Inspect Sessions, Archived, and Trash. Select Restore if needed. The sidebar shows active root chats. Select Refresh after the owning environment is available. For Session file unavailable, reconnect the original guest home or recover its native transcript. A saved usage record alone cannot resume a conversation.
Usage is partial, unknown, or older than the last reply
Wait for the agent to finish its response. Use Refresh. Open Session usage and read the coverage, assumptions, and unpriced reasons. If a refresh failed, the dialog can show the last recorded values. Close and reopen it to retry. If the message concerns the usage database, check Records folder. Refreshing cannot reconstruct a measurement the provider never recorded.

Records, restart, and removal

The records drive is missing, or another instance owns the records
Check Settings → General → Records folder. Reconnect the original drive or locate the same complete records folder. If another instance owns it, close that instance normally and restart this one. Keep the saved location and lock files in place. Records recovery.
Restart reports a copy, final usage, or database failure
Keep the original records and both drives connected. Check free space and the reported destination. A pending move can retry on a later restart. A final usage or database close failure can keep the app open after processes have ended. Reconnect the original location and retry. If the database is damaged, arrange offline recovery from a matching backup.
Removal reports a changed target or incomplete progress
Open Review incomplete removal… or reopen the appropriate removal preview. Compare the session name, folder, guest home, and completed steps. Continue only if the remaining target is the environment you chose. If the target now belongs to another project, keep that environment and report the mismatch.

When you ask for help, include the Tugboat version from General, the macOS version and Brig source from System Checks, the agent, the action, and the exact error. Include only relevant, redacted diagnostic lines. Keep account records, device codes, private project paths, and chat contents out of the report.
