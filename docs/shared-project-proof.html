Shared project guest proof

Run this acceptance check on an Apple silicon Mac with the prepared Tugboat development runtime. The check creates a project, a Brig session, a policy, and runtime storage under a private temporary directory. The check uses public downloads and synthetic credential data.

Run the check where Hull can inspect its virtual machine and gateway processes. Brig uses those process checks to decide whether it can reuse a running guest.

node scripts/acceptance/check-shared-project.mjs

Read evidence.json at the path printed by the check. The report includes the image digest, both program versions, and the guest layout. The check stops and removes its guest and detaches its private Hull store. Use --keep when the next check needs the same running guest.

Image and executables

The profile uses an immutable Linux ARM64 Claude Code stock image from Brig's signed public registry. Tugboat's require setting and Brig's default signer check cover the image and the boot assets. The runner also tries a public Ubuntu image against the same policy and checks for a signature refusal.

The Codex release workflow signs the pinned Linux ARM64 package, which includes the resources used by its workspace sandbox. The runner checks the archive and bundle hashes and verifies the signature for the exact OpenAI release tag. It stages the package in the guest home and compares the executable hash on both sides of the mount. The guest policy allows provider endpoints only, so the guest does not obtain programs from a package server during preparation.

Application setup

The app prepares one tugboat-project reference per project. The plan pins the stock image digest and names a persistent guest home under the Brig state directory. The app uses the bundled Brig and Hull tools and requires the default Brig signature policy.

The Mac downloads the pinned official Codex package on first preparation. The app checks the archive and Sigstore bundle hashes, verifies the exact release signer, and installs the package in /root/.tugboat-codex-0.167.0. The package manifest covers its 44 files, including the executable, workspace sandbox helper, and other resources. The installed package is verified again before a Codex chat starts.

If a package check fails, stop the guest and prepare again. The app can replace the damaged files in its package directory after it verifies the replacement. A link or unexpected file owner stops the repair for review.

Preparation checks the running Hull image digest, Claude's temporary credential mount, and both agent versions. Each chat names its own executable against the same Brig reference. The guest shell uses that same reference and needs no provider sign-in. The project has one deny-by-default policy and its initial allowed hosts include both providers.

One guest and two launch targets

The proof profile uses Bash as the neutral profile executable. Brig v0.5.2 accepts a session policy on an agent profile. Each proof launch names the agent executable and passes that agent's normal arguments to the same Brig session. The project mounts at /work/sample project. The guest home mounts at /root.

Codex uses /root/.codex for its settings and saved sessions. Claude uses the memory filesystem at /brig/claude for its access copy. The profile binds Claude's persistent configuration and history paths under /root/.claude into that filesystem. Stopping the guest clears its memory filesystem. The two guest processes can access the same project and share the guest permissions.
