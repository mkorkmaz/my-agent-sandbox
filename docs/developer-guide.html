Developer guide

A project can contain a Codex chat and a Claude chat with the same native session identifier. Each chat must reopen in its own guest. Start with the action, its owner, and the identifier that selects its target.

Set up a checkout

The native target is Apple silicon with macOS 15 or later. Install Xcode and its command line tools, Rust with Cargo, and Node.js with npm. Use the recorded versions in config/development-versions.json to reproduce a build. The supported Node.js ranges are in package.json. Keep the npm and Cargo lockfiles with changes to their manifests.

From the repository root, install the locked web dependencies and build the interface. The build checks TypeScript before Vite writes the web assets into dist/.

npm ci
npm run build

For interface work, npm run dev serves Vite on 127.0.0.1:1420. The fixture harness supplies native commands and events to interface tests. For interactive desktop development, npm run tauri -- dev prepares the native runtime and starts Tugboat. Opening the desktop app runs its normal startup against the selected records directory, including any necessary import. Use a disposable macOS account or isolated test setup for migration work.

The first native preparation can download and build pinned dependencies. Tauri's standard hooks use the default preparation mode, which can sign local helpers. The pull-request workflow uses a separate mode for native tests. Use the commands in Choose checks when testing under a signing restriction.

Interface and command contracts

The window contains static HTML and TypeScript controllers. src/main.ts wires selection, preparation, accounts, history, and terminal navigation. For a feature with an existing controller, put behavior beside that controller. Keep the entry point responsible for passing its context and callbacks. The shared Zustand store in app-data.ts holds the selected project, accounts, terminal lists, and other display values.

At an asynchronous boundary, capture the project and environment before starting work. Use sameProject to check the identifier, environment, and project epoch when the result arrives. Use sameProjectView for a result that belongs to one opening of Project Settings. A revision from RequestState distinguishes an older request for the same screen. A late response can otherwise put the first project's policy text in the second project's editor.

Use the controller's existing state transitions. For forms, FormState retains loaded values after a failed save and invalidates pending work on reset. For dialogs, showDialog manages the active modal and restores keyboard focus. The sidebar queues preference writes so a slow restore cannot undo a recent resize. Render titles, paths, and diagnostic text with textContent. Keep control labels and keyboard behavior consistent with the design guide.

Change a native command

Tauri carries inter-process communication between the web view and Rust. The interface calls invoke with a command name and named arguments. Rust registers commands in tauri::generate_handler!. Extend an existing command when the new action fits its contract. For a new command, implement the handler in the owning module and register it in the entry point.

Decode external values into the appropriate Rust type, then resolve ownership from native records. Preserve the established camelCase fields and serialized enum values. Keep time-consuming file and process work off the window thread with the existing blocking-task pattern. Return the result needed by the controller. A TypeScript annotation on invoke<T> describes the expected response. The Rust handler still has to validate incoming identifiers, arguments, and target state.

For an event, inspect the emitter and the listener together. A terminal-exit event identifies a terminal and its project. Dashboard updates carry a sequence. Use those fields to ignore a late update and reconcile with a snapshot after a subscription or view change. Exercise the sequence with delayed promises in the interface harness. Keep the window permission set limited to the operations the UI needs.

Desktop lifecycle and settings

Rust resolves the records location before it starts the usage worker. It then creates the window. The web view invokes frontend_ready to show and focus it. Starting the worker and completing database activation are distinct events. Code that needs usage records obtains the verified store from the runtime. Keep unrelated interface startup work independent of a slow import.

For a new menu action, add the native item and its action identifier in desktop/menu.rs. Wire the corresponding menu-action listener in TypeScript. Update update_menu_state when availability depends on a selection or process. Expose the same behavior through an accessible control where the product design calls for one. Check keyboard activation in each applicable view.

Quit, window close, and a records move that needs a restart share the shutdown path. The lifecycle cancels provider login, drains terminal processes, waits for host commands, flushes provider work, scans final usage, and closes the database before allowing exit. If you add a background writer, include its final write or cancellation before the relevant store closes. Simulate a failed final write. The user must still be able to recover and retry.

Choose the scope of a preference

Application defaults live in settings.json. The profile and allowed hosts have separate Codex and Claude values. Project overrides go through the project registry. CPU count, memory, and image verification apply across that project's environments. Network mode belongs to one environment. A resource change can invalidate preparation for both agents. The native save path checks running processes and actual Brig state for the affected environments.

For an execution preference, follow its value from the form to native validation, persisted settings, effective project settings, and the checked plan. For an interface preference such as sidebar width, follow interface.json and the preference save queue. Add a decoding fixture for an existing installation. Check missing fields, invalid values, and how defaults apply when a project already has an override. The settings save command writes the chosen settings before it attempts to apply Brig telemetry. Preserve its separate report of the recorded Brig state.

Projects, policies, and preparation

A stored ProjectRecord owns a folder identity and an Environments collection. The public Project value represents a selected environment with its project's shared fields. Add an environment-specific attribute to the persisted environment and its resolved view. Keep the one-environment-per-agent constraint. If two agents update the same project, the second update must retain the first agent's environment.

Registration checks the selected folder and its write access. Folder identity includes filesystem evidence such as inode and volume identity. A different folder can later occupy the same path. Availability checks preserve the registry entry for a missing volume. When changing the rescan, test a missing folder, the original volume returning, and a replacement at the same name. Verify recent ordering and keyboard focus survive a background refresh.

Trace a setup failure

  1. Resolve the session. prepare_project selects a new session reference or adopts a matching Brig session. It prepares the policy and binding. With several valid candidates, preparation returns a choice. Recheck a supplied choice against the current candidates.
  2. Read the plan. checked_environment resolves the environment from the registry. It checks folder identity, setup stage, current policy, profile, Brig plan, and the separation of private records from exported shares. The interface receives a fingerprint for these settings.
  3. Start the guest. prepare_environment uses the reviewed fingerprint. It records the attempt token and terminal identifier. The operation gate rejects conflicting work for the same environment.
  4. Complete the matching attempt. Completion checks the current attempt, running guest, agent version, and plan. A completed attempt records either the verified state or an error. A stale completion from a previous attempt cannot mark the new one ready.

When changing a stage, check its serialized spelling in Rust and TypeScript. Follow its uses in preview, prepare, launch, and removal. A new intermediate stage needs a defined response to restart or retry. Check a changed plan between preview and launch, a terminal that exits before the interface reads its snapshot, and an older exit after retry.

Maintain a policy or boundary check

Policy document ownership and binding ownership are separate. A document can be external or shared, even if Tugboat owns the binding. Route save, accept, attach, and detach through the policy state and editor. Recheck the current document before writing. Invalidate preparation after an edit. Exercise an external binding and a competing edit with the old fingerprint.

The boundary report records the environment and the fingerprint used for its probes. The probes check the guest kernel, writable share, outside-file visibility, and network behavior. Keep the outcomes pass, fail, and inconclusive distinct. Preserve files whose ownership changed during a probe. A changed plan, failed cleanup, or unreachable comparison destination affects what the result can establish. A boundary report is diagnostic evidence for that run.

Project operations and removal

Operation owns the set of Git, test, and diagnostic actions. Its needs_guest decision determines whether the operation needs a verified running guest and a current plan fingerprint. Git and project tests run in the selected guest. Doctor, info, policy checks, and logs call Brig on the Mac for the selected target. For the test button, native code detects a supported manifest and chooses a fixed command. The user's repository still determines what its test script executes.

For a new action, choose its execution location first. Build an argument vector with the existing Brig adapter. A fixed shell fragment inside the guest can use its project environment variable. Keep path or label values out of generated shell text. Name the terminal purpose so the sidebar and stop logic can identify the process. The worked Git example covers the full route.

Stop, forget, and remove have different effects. Stop verifies the Brig reference, records the stopping stage, ends the selected environment's guest processes, and rechecks the target before the stop command. Forget removes the registration of an unavailable project and stops its monitoring. Removal uses a preview, its fingerprint, the confirmation text, and saved progress. A single-environment removal and an all-environment removal have different target sets.

For cleanup changes, inspect Removal::next_step. The ordered steps cover optional sign-out, environment removal, binding cleanup, policy handling, and record removal. Each completed external effect has to agree with the recorded progress when recovery resumes. Preserve external or shared policy documents. Exercise failure between steps, a change after the preview, an unaffected sibling environment, and the last environment in a project. Check that project source files survive each path.

Brig, hull, and the host runtime

Brig manages sandbox sessions. The packaged runtime uses hull with the hvi backend. platform/runtime resolves the runtime directory and checks the manifest and file digests. Host inspection reports the effective tools. An empty Brig CLI path selects the bundled executable. A user-specified Brig path still needs a compatible version. Keep the package manifest and runtime resolution in step when changing a helper.

Use platform/command.rs for bounded host subprocesses. It clears the inherited environment, installs an explicit set of variables, and tracks cancellation, timeout, exit status, and excess output. The Brig environment supplies the bundled helper paths and a private registry configuration for public images. Inspect the result status before parsing output. When reading Brig JSON, check the API version, result kind, and required data through the existing adapter.

The Brig plan check verifies the profile, session, writable share, limits, network posture, image verification, and bound policy. It rejects forwarded host credentials, host skills, and published ports. Extending the plan affects both plan validation and what the user can review. Add ready and refused fixtures with the same schema version. Check an otherwise successful response with an invalid field. A successful process exit alone says nothing about the target or the shape of the payload.

Change account behavior

provider_login manages a separate attempt for each provider. Its worker moves through preparation, browser authorization, exchange, and save. The attempt identity prevents an old worker from publishing a cancelled result. Cancellation is possible before saving begins. The interface receives a status revision, a message, and any information required to complete the browser step.

Keep the renewable record private to the verified records directory. A managed guest receives only the access material required by its provider. For ChatGPT, preserve binding identity, the account generation, and the receipt used to recognize a managed copy. For Claude, the guest helper updates the account entry while retaining independent connector credentials. When a refresh result is uncertain, preserve the provider's reconnect behavior. Replaying a refresh token after rotation can invalidate the saved session.

Use synthetic credentials for tests. Cover a late callback after cancellation, a write failure after a successful exchange, a missing records volume, and an existing guest file with unrelated keys. Review returned errors, status events, and logs for tokens or account contents. If a change depends on the real browser protocol, record the protocol version and the separate integration check it requires.

Scope an additional agent

A third agent would change several contracts. The current AgentKind enum, definitions, environment collection limit, and SQLite agent_kind constraints cover two agents. Trace how the new agent assigns session identifiers, verifies profile and version, reports permissions, resumes a chat, and stores native history. Decide which credentials belong in its guest. A new provider also needs an account lifecycle and shutdown behavior. A new logo or command builder alone would leave the persisted registry and database unable to represent that agent.

For a staged implementation, begin with an isolated command-builder test and a captured plan. Exercise environment identity and lifecycle next. Then connect the interface and saved history using fixtures. Preserve explicit unknown usage when the agent lacks a verified measurement source. Before enabling the agent, exercise a mixed project with existing Codex and Claude records and a restart between creation and resume.

Native terminal

A pseudo-terminal (PTY) connects an interactive process to the terminal view. Rust opens the PTY and manages process groups, input, resize, output, and exit. A macOS AppKit view uses the Ghostty terminal library to interpret bytes and draw cells. TypeScript supplies the visible rectangle and focus. For a text composition issue, begin in TerminalInput.m. For a missing glyph, inspect TerminalDrawing.m and the font setup. For an orphaned process after close, begin in terminal/pty.rs.

A native view and a guest process have distinct lifetimes. Terminal startup reserves an identifier before it attaches the view and spawns the child. Closing the reservation blocks a late attachment. The process manager shares a start/stop gate for the equivalent race at process creation. Deliver native view work on the main thread. Preserve the bounded input queue and the output reader's acknowledgement when changing throughput.

Hiding a view keeps its process available. After a child exits, the registry can retain its output. The current limits are 16 live processes and 32 completed views. Keep completed output outside the live capacity count. Use the environment target for guest commands. The local terminal opens a host shell in the registered folder. A stop intended for one guest must preserve the local shell and the other agent's guest.

For a layout change, use TerminalLayoutQueue to coalesce requests. Recalculate when the sidebar or dialogs change the available rectangle. For a close race, the adapter ignores an expected “Terminal closed.” only for the affected target. Exercise output after a view switch, focus after close, and an input method that commits several characters. Use native composition tests for AppKit behavior and the interface fixture for navigation.

Conversation history and dashboards

The conversations module reads agent-owned files from the checked environment. Codex rollouts and Claude transcripts use different formats. Each adapter produces source evidence about the session, guest namespace, project path, parent, availability, and usage. A native identifier can recur in another guest. Keep each observation scoped to the project and environment through the store, event, and interface cache.

The history graph resolves root and descendant relationships. A normal fork remains a separate chat. A recognized subagent contributes to its root's family total. Missing, inconsistent, or unsupported relationship evidence has an explicit status. Preserve the session's own measured usage in that case. A root chat action checks its family for running processes. Archive, delete, and restore change the saved display state and preserve the native transcript and recorded project total.

There are three read paths for the project dashboard. saved_project_dashboard loads saved usage before a guest check. recorded_project_dashboard refreshes from SQLite and can keep availability that an earlier live observation verified. project_dashboard checks environments and synchronizes source history. The monitor sends project-usage-updated for changed observations. In the interface, DashboardState orders events and requests and retains usable data on a failed refresh.

For a new row field, decide whether its source is a verified observation or a saved fact. Define its display when the volume or guest is unavailable. Propagate it through the summary, detail query, and frontend types only where the feature requires it. A detail cache uses project, environment, and session identity, plus a revision to detect changed content. Test an old snapshot arriving after a new event and two guests with the same native session ID.

Usage parsing and prices

Codex parsing tracks a cursor for each rollout source. The cursor records the file identity, header fingerprint, byte offset, and reconciliation state needed to resume counting. An incomplete last line can receive more bytes later. Replacing or truncating the file can require a replay. Match an exact request to its source and previous observations before increasing a count. Store progress with the facts it explains.

Claude usage comes from assistant messages in main and subagent transcripts. Repeated stream entries can refer to one response. The reader uses the provider message ID and source evidence to reconcile them. The input total includes ordinary input, cache reads, and cache creation. Claude's cache duration fields and Codex's cache duration fields have different meanings. Keep provider-specific values in the owning parser.

usage summarizes requests and prices them against dated provider tables. A measured zero, an unmeasured turn, and an unpriced request give different results. Preserve those distinctions through storage and rendering. A new rate needs an exact model match, applicable billing conditions, the source date, and tests at relevant thresholds. A supported correction uses the saved price snapshot and retains the previous evidence. Catalog changes must preserve the cost already recorded for an earlier request.

For a calculation change, compare own-session and family totals. Then compare the mixed-agent project total, including archived and deleted chats. For a cache percentage, divide the summed cache reads by the summed inputs when both are known. For example, counts of 10/20 and 10/80 give a total of 20/100, or 20%. Averaging the two percentages would give 31.25%. A missing count requires an unknown indicator. The UI calls the recorded price an API equivalent.

Its marker and database identity let the app detect a missing or replaced folder. Project source, guest homes, and native transcripts have separate owners. A stored path alone does not establish that a file still belongs to this dataset.

Change the SQLite read or write path

The database has a unique environment row per project and environment. A session group adds its native session identifier. A record slot can represent the selected record or another saved guest variant. The variant's map key and the record's own guest namespace can differ in imported data. Preserve both values. Requests have an ordinal within a turn. Keep the original order when reconstructing details or corrections.

Choose the narrowest existing read that answers the caller. A dashboard can use metadata and stored summaries. A detail view can load the slots for the selected family. A scanner starts with headers and loads full records only when it needs them. If source bytes appear after the initial scan, defer the read until the saved turns are available. Advancing a cursor without loading its prior facts can silently drop usage.

save_partial_environment differentiates a loaded record from a header-only update. A partial write must preserve the facts of omitted sessions. Maintain that distinction when adding a summary field. Add an interrupted append test that fails between recording a request and recording its cursor. On the next scan, expect the last committed totals followed by one application of the new fact. Check a quiet second scan for unnecessary reads and writes.

Preserve existing datasets

The current SQL schema version is 1. Version 2 on .tugboat-data.json means SQLite activation completed for this records directory. Legacy JSON usage ledgers have their own versions. For a new database field, plan the upgrade for an already active database as well as a new install. Changing the initial schema alone would leave existing installations with the old table layout.

During initial import, the importer inventories the original ledgers, creates the required backups, and builds usage.sqlite3.importing. It verifies the import receipts and field parity against the sources. It publishes the canonical database before changing the directory marker. An activated dataset requires its original verified database. Retained ledgers are historical inputs and can be older than the most recent usage. Reopening after a failure must preserve newer facts and report a missing or damaged database.

For a records move, the current writer must finish and close. The move logic recovers a hot rollback journal through SQLite, copies the closed database, checks identity and integrity, and verifies the copies. The pointer changes only after validation. “Locate” reconnects the same dataset at another path. Exercise failure before publication, a changed source, an interrupted copy, and a foreign dataset at the proposed location. Use temporary directories and generated data.

Two worked feature changes

Add a “Recent commits” guest action

Suppose the requested feature shows the latest ten Git commits in a terminal for the selected agent environment. Both guest agents should be able to use it. The output should remain accessible when the command ends. The existing staged-diff action already exercises the controller, command dispatcher, and terminal registry.

  1. Find the git-staged-diff control in the root index.html. Add a sibling control with a clear label and identifier. In src/projects/operations.ts, add its mapping to an operation such as git-recent-commits. Pass the captured project, environment, and current fingerprint to the existing OpenTerminal callback.
  2. Add the operation to the TypeScript ProjectOperation union. Add the matching Rust Operation variant and terminal purpose. Mark the new operation as requiring the guest. This reuses native checks for a current plan and a running environment.
  3. Build the fixed guest Git command in projects/operations/mod.rs. Follow the existing $BRIG_PROJECT handling for a checkout with spaces. Give an empty repository an intelligible result. Return an execution error when the command fails for another reason.
  4. Add the caption to terminalNames and the purpose to Rust's runs_in_guest. This lets Stop end that guest process. Check the sidebar after completion and the existing auxiliary-terminal concurrency rules.
  5. Use a temporary Git repository with known commits to check output and order. Add an interface fixture for the selected Claude environment in a project that also has Codex. Assert the exact command arguments sent by the UI, the retained output caption, and the response to a stale fingerprint.

The change reuses the existing start_project_operation registration and terminal history. Its public change is the added operation value.

Show how many requests have a price

Suppose a maintainer wants the usage dialog to show “3 of 4 recorded requests priced.” A small dollar subtotal can then be understood when one request has no known price. First check whether old records already contain the evidence this display needs.

  1. Inspect Summary.requests and Summary.unpriced_requests in Rust. The summarizer counts recorded requests and increments the second field when the cost is absent. A measured zero-dollar request still has a price.
  2. Choose the scope of the label. For a whole root chat and its descendants, take combinedUsage from ConversationUsageDetails. For a single agent's row, take that agent's ownUsage. Summing family and child values would count children twice.
  3. Format the label in src/usage/usage-format.ts from requests - unpricedRequests and requests. Render it in usage-details.ts. For no recorded requests, use “No recorded requests.” Preserve the existing unknown indicator for a turn without any usage event.
  4. Use a fixture with four requests, including an unpriced request and a priced zero. Expect three priced requests. Open the same saved details after reopening the dialog. Check that the label uses the current family if the user switched roots during a pending read.

Both counts already round-trip through stored summaries. The example works with saved data using the existing response. If a future measure requires new evidence from a transcript, define the unit, source, and meaning of an absent field first. Then update the provider parser, store codec, summary calculation, and display. Rebuild old summaries only when their retained facts establish that measure.

Pull requests run frontend tests and the web build on Linux. A change that touches native inputs triggers native checks on a Mac. A separate job checks formatting. A push to trunk runs the release workflow, which builds an ad hoc signed package and can publish its disk image. The Developer ID release script uses release credentials and notarization. Choose that script only for the corresponding release task.
