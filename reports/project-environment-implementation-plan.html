Both agents share the guest filesystem, processes, and project network permissions. The isolation boundary is between projects. A directory per agent organizes state; it cannot isolate credentials from another process with the same guest privileges. This plan assumes users trust both agents with the project's guest access. Keep renewable credentials on the Mac. Show this behavior in Project settings before users prepare the shared environment.

Delivery order. Complete phases 1–3 before releasing the new ownership model. Deliver phases 4–7 as separate increments. The diagnostics work can be developed alongside preview work after the project contract is stable.

1. Prove the shared guest works · Medium

Scope. In a disposable development project, prepare one agent-independent Brig profile and a guest image that can run both supported command-line programs. Establish how the release build will obtain the two programs and verify the image under the default signature policy. Launch each agent explicitly against the same Brig reference. Check the actual interactive terminal path. Keep provider access delivery and each agent's permission options in its adapter.

Acceptance criteria

  • Brig reports one sandbox reference and one project mount. Both programs report their versions inside that sandbox. Each sees a test file written to the project by the other.
  • A Codex chat and a Claude Code chat each accept terminal input and resume after a guest restart. Changing the agent selector preserves an already open chat and its terminal target.
  • Codex passes checks for both supported sandbox settings. Claude passes its manual permission check. Each agent uses its intended provider. Renewal secrets remain on the Mac, and Claude's temporary access copy clears on stop.
