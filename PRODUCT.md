# Tugboat

**Agent Sandbox**

## Platform

web

The frontend runs inside a Tauri desktop application for Apple silicon Macs with macOS 15 or later. Native macOS windowing, menus, folder dialogs, and keyboard behavior govern the interface. The app uses a fixed dark sidebar and light workspace.

The main window opens maximized to the screen's usable area with its native titlebar. All Lucide interface icons use `stroke-width="1.5"` as the shared design rule. The requested Codex and Claude brand marks use filled shapes instead.

## Stack

The implementation plan uses Tauri 2, Rust, Vite, and TypeScript. Verified versions are recorded in config/development-versions.json.

## Product Purpose

The user selects a project folder and chooses Codex or Claude Code. Each agent runs in its own Brig environment through an embedded libghostty terminal. An open conversation supports subsequent messages and approval requests. Saved conversations can be resumed. Agent environments have separate identities, profiles, policies, guest homes, and lifecycle state.

Projects lists registered folders in a table, ordered by last opening, with current Git branches and path tooltips. Add new project, with a leading plus icon, appears only at the right of the Projects header. The native agent select appears only beside New Chat inside the project and selects the project's agent environment. The sidebar lists projects until one is selected, then shows that project's active sessions from both agents. Each sidebar session begins with a 16px Codex or Claude logo in the same color as its text. Accessible names retain the agent name. The session table shows that name in a small neutral pill beside the timestamp below each title. Projects always returns to the library. Session titles remain on one line with an ellipsis and a full-title tooltip. The sidebar resizes from a 280px minimum using its right-edge divider or the keyboard. Its preferred width persists and the workspace retains at least 480px. The minimum window width is 760px; wide tables scroll horizontally.

Project folders are checked automatically when the app opens. Unavailable folders are checked again every eight seconds while the project library is visible, and immediately when the app regains focus. Checks pause in Settings and selected project views, stop once all folders are available, and preserve keyboard focus. There is no manual rescan button. A successful scan keeps the project identity, Brig environment, saved usage, and opening order. Persistent volume UUIDs identify disks across restarts when available. Legacy records can recover changed device numbers using matching inodes and known creation times; replacement folders and different known volumes remain unavailable.

Settings includes Records folder. The default is ~/Library/Application Support/Tugboat, with automatic migration of earlier sh.brig.desktop records on first launch. Selecting an empty folder schedules a move for the next app restart; a visible destination and cancel action keep the pending change reviewable. Settings, projects, sidebar preferences, installation progress, boundary reports, both shared provider records, usage ledgers, and immutable backups move together. The default directory retains only the location pointer and its lock when a custom folder is active. Copies are verified before committing the pointer and cleaning the old records. Incomplete copies cannot become active. An unavailable disk leaves location recovery accessible and never creates a replacement dataset. Restart uses the normal process confirmation and final usage flush.

Application Settings contains Providers, with one shared browser sign-in flow for ChatGPT and Claude. Both accounts can connect before a project is registered or selected. ChatGPT uses device authorization. Claude uses proof key for code exchange (PKCE) and a temporary loopback callback. Native Rust owns preparation, browser waiting, token exchange, saving, cancellation and failure states. Late results cannot replace a cancelled attempt. Account updates preserve navigation and focus. Project settings contain project configuration and environment actions only.

One ChatGPT account serves Codex environments. Existing saved ChatGPT sign-ins can still be adopted explicitly. Different users or workspaces require a source choice. Its private renewable record stays at <records folder>/chatgpt/session.json. The shared Claude record lives at <records folder>/claude/session.json. Both move with the other records. Refresh tokens stay in those private records. Codex guests receive access copies. Managed Claude guests receive access copies in memory, with a null refresh token. The stock guest's Python 3 updates only the Claude account section and preserves independent connector credentials. Host Claude credentials are not imported.

New Chat and Resume verify the shared provider account before starting. Stopping a guest clears its temporary copy while preserving the shared account and transcripts. A later chat restores its access copy. Shared sign-out requires the relevant chats and guest terminals to end. Removing or forgetting one environment preserves both provider accounts. Project network policies continue to govern model connections. Project account errors open the corresponding heading in Settings, Providers.

The saved location transaction upgrades older two-field directory markers. The active directory is complete; a pending copy or cleanup source remains incomplete until its recorded move finishes. Unknown legacy copies, invalid markers, mismatched identities, and explicit incomplete flags remain unavailable.

Each project supports multiple simultaneous chats across its agent environments. Selecting an open chat restores its own native terminal and scrollback while other chats continue. Its toolbar title begins with the same monochrome agent logo and retains the full title in its tooltip. New chats appear immediately in the sidebar and acquire their saved title once history is available. Close terminal affects the selected terminal. Codex's terminal status parser supplies its working or thinking icon; Claude does not use that parser. Reduced-motion preferences retain a static activity icon. Rust assigns each new Claude chat a UUID. Resume uses the same native ID without creating a fork.

Each root chat appears once in the table and sidebar. Both agents include all linked subagents, including nested subagents. Normal conversation forks remain separate chats. Subagents cannot be resumed or have their saved states changed independently. Unresolved relationships have a read-only Unlinked subagents recovery area. Claude usage includes recorded main-session and discovered subagent messages, with ordinary input, cache reads, cache creation, and output. Stable message IDs prevent duplicate counting. Claude coverage remains partial because missing transcripts, unverified relationships, and unrecorded work limit coverage. User prompt attribution remains unavailable. Supported Anthropic token prices appear with their saved dates, source, and assumptions. Mixed-project totals include known usage from both agents. Missing or invalid Claude counts remain unknown, and saved usage survives transcript loss.

The project header stays fixed, with its name and small branch label above the folder path. The Brig session reference is right-aligned below the settings icon. The settings icon opens a wide modal for project preferences, policy, diagnostics, and environment actions. Resource settings and operations target the selected agent environment. Opening a configured project starts its selected environment automatically with saved preferences and verifies the guest agent in the background. An already verified running environment or a start in progress is reused. Startup never opens project settings or takes terminal focus. The session table and usage remain visible while New Chat and saved-session resume wait for verification. Inline startup errors offer Retry environment without repeating configuration. Explicitly stopping an environment does not immediately restart it; Start environment or reopening the project starts it again. Active chats are preserved when changed settings cannot yet be applied. Only unresolved configuration choices show Review project settings.

Root chats can be archived, moved to Trash, and restored. These actions target one environment's chat. They preserve source Codex rollout files, Claude transcripts, recorded subagent states, and historical project usage. Archive and deletion require that chat's relevant terminal processes to be ended. Project settings provide separate previews for removing the selected environment or all project environments. The preview identifies affected sessions, guest homes, bindings, and policies before confirmation. Stopping or removing one environment preserves the other environment. Forget retains its record-only behavior and preserves project files, Brig environments, guest homes, and saved usage.

Saved Codex sessions and token events come from each Codex guest home. Claude transcripts come from that environment's persistent .claude/projects directory. History readers filter by the verified guest project path and its subfolders. Reading history does not start an environment. Each environment has separate history monitoring and a separate ledger. A chat's identity combines project, environment, and native session ID; equal UUIDs in different environments remain separate. Exact source ownership and parent relationships support the observed guest Codex 0.167.0 format. Claude child transcripts retain the root session UUID and their own agent ID. The bounded importer checks adjacent parent metadata against the spawning Agent or Task call. It retains unverified children in recovery. Standalone roots remain separate. Codex physical request identity combines the verified guest-home namespace, provider, origin thread ID, and response ID. Guest namespaces remain isolated; equal counters do not prove identity. Legacy records retain their usage with unknown source coverage until reliable evidence resolves ownership.

Codex session usage separates own, subagent, and combined amounts. Expandable agent sections retain their own turns and requests. User prompt counts remain separate from agent turn counts. Proven prompt attribution links to source requests or unmeasured turns; unassigned work remains explicit and included. A selected child's details include only that child and its descendants, excluding ancestors and siblings. Open details refresh when the selected subtree's records or relationships change, preserving disclosures, focus, and scroll position.

Cached input shows a percentage only when its relevant counts are fully known. Aggregate percentages divide summed cached input by summed input. A turn without request measurements has unknown usage; an exact zero-token request is measured zero. Complete, partial, or unknown coverage describes persisted source records, with no guarantee of complete account billing or every short-lived subagent record. Cache and pricing knownness remain separate. Requests retain dated OpenAI rates checked on 2026-11-10 or Anthropic rates checked on 2026-11-13. Later catalogue changes do not reprice saved requests. Anthropic writes use separate 5-minute and 1-hour rates. Missing or nullable billing metadata uses labelled standard/global estimates and default 5-minute writes. Malformed non-null fields remain invalid and unpriced across restart. Reliable later metadata resolves assumptions with correction evidence and the saved tariff. Saved unpriced Claude counts can be backfilled offline. These token API equivalents exclude subscription charges, account discounts, server-tool charges, and taxes.

Usage ledgers use schema 2. The first migration write preserves a schema 1 ledger as a byte-for-byte, immutable `.json.v1.backup`. Migration preserves saved states, request keys, amounts, dated prices, and prior corrections. Verified source replay can attach ownership or correct amounts without counting requests again; amount and rate corrections retain separate evidence. Conflicting backups and unsupported schemas stop writes and preserve the files. Closing the application while an agent or terminal process runs requires confirmation.

Project registry migration retains an immutable projects.json.v1.backup. Existing Codex references, policies, guest homes, ledger paths, and prior ledger backups remain unchanged.

Claude uses the Brig boundary with manual permission requests; the Codex sandbox option applies only to Codex. Each implementation item is completed and reviewed separately when the user requests it. reports/imp-plan.html records progress, measured tokens, API equivalents, and comparisons with the original estimates.

Both Codex projects and the main Claude chat continued. Successful shared ChatGPT sign-out also preserved a new reply in the same open Claude session.

The original records location was restored exactly. All 18 normal record files remained byte-for-byte unchanged after the latest app reopened. Four test guests were stopped, five unrelated inventory entries remained unchanged, and the test disk was detached. The temporary CLI wrapper was removed. Other test homes, project files, the disk image, and the custom profile remain available for review. The initial Codex setup retry and stock Claude auto-update warning have no established cause. ## Operating Context

The primary workflow starts with a local folder. An empty CLI path selects bundled Brig. A compatible saved custom path selects that CLI. The app includes patched Brig and hull, signed hvi/Vz runners, cosign and the required ext4 tools. The patches support app-relative disk tools and spaces in shared folder paths. Source and toolchain pins are in config/brig-compat.json, config/hull-compat.json, config/brig-runtime.json and config/disk-tools.json. Codex and Claude Code run in separate Brig environments. The UI language is English. The interface uses locally bundled Google Fonts Inter, including controls and document previews. Native macOS titlebars, menus, and dialogs retain system typography. Lucide Folder and Settings icons accompany the sidebar labels.

The fixed palette uses #1E1E1E for the sidebar, #F1F1F1 for the workspace canvas, and #4D8DFF for primary workspace actions and sidebar selection. Only the Projects library has a dot grid with #A8C7FF dots, a 1px radius, and 20px spacing. Text on blue fills uses the user-specified #F1F1F1. The sidebar shows the application icon beside the white Tugboat name, with Agent Sandbox underneath. Fields, secondary buttons, and dialogs use white surfaces. Focused text fields use a 1px #4D8DFF border. Buttons have no focus or pressed border; keyboard focus uses an underline or a changed surface. The workspace uses light appearance and the native window header uses dark appearance, independent of system appearance.

Settings uses a plain #F1F1F1 canvas and white rounded information groups, with 1px #F9F9F9 separators between groups. Its type hierarchy separates the 24px page title, 16px section headings, 13px field labels, 14px control values, and 12px hints. Editable controls share a 36px minimum height and a light #B8B8B8 resting border. Native HTML selects use a Lucide chevron with the same control surface while retaining native option menus and keyboard behavior. The macOS window explicitly uses Dark Aqua appearance and an opaque native titlebar. Its content frame excludes the titlebar, and the document and form controls use light appearance.

The native terminal uses Consolas at 14pt. If Consolas is unavailable, it uses locally bundled Google Fonts JetBrains Mono. The dark terminal theme retains #FFE735 foreground text and the existing ANSI palette, cursor, selection, padding, and cell-height adjustment.
